# 11 · 搜推广名词与缩写速查

> 面向刚接触搜索、推荐和广告系统的读者。目标是帮你快速看懂本项目的代码、配置、日志和其他文档。
> **最后核验：2026-09-01**。同一缩写在不同公司可能有不同口径，本文以 recsys 仓库的实际用法为准。

## 0. 先用两条链路建立全局观

```text
自然搜索 / 推荐：
Query 理解 → Recall 召回 → Pre-rank 粗排 → Rank 精排
→ Rerank 重排 → 展示 → 行为回流

搜索广告：
Query 理解 → Ad Recall → Relevance 相关性门槛
→ pCTR/pCVR 预估 → Bid/eCPM 竞价排序 → GSP/VCG 拍卖计价
→ 曝光/点击/转化 → 校准、归因、智能出价和实验
```

先记住一个原则：**召回求“别漏”，排序求“谁更好”，重排求“整页更好”，广告还要求“钱算对”**。

## 1. 五分钟必记的 20 个词

| 名词 | 全称 / 中文 | 一句话理解 |
|---|---|---|
| Query | 查询 | 用户输入的搜索词，经归一化、分词、意图识别和改写后进入召回。 |
| Recall | 召回 | 从大量物品中快速找出几百个候选，重点是覆盖率。 |
| Rank | 排序 / 精排 | 预估每个候选的价值，再按分数排序。 |
| Rerank | 重排 | 在单物品分数之上处理多样性、频控、广告负载和整页体验。 |
| Embedding | 向量表示 | 把用户、物品或 query 变成数值向量，距离近表示更相似。 |
| ANN | Approximate Nearest Neighbor | 牺牲少量精度，换取大规模向量检索速度。 |
| HNSW | Hierarchical Navigable Small World | pgvector 使用的 ANN 图索引，快但需在召回率与延迟之间调参。 |
| CF | Collaborative Filtering，协同过滤 | 用“用户与物品的共同行为”做推荐，如 ItemCF、UserCF、Swing。 |
| RRF | Reciprocal Rank Fusion | 不硬比不同召回路的分数，而按各自名次融合。 |
| CTR / pCTR | Click-Through Rate / predicted CTR | CTR 是真实点击率；pCTR 是预测的点击概率。 |
| CVR / pCVR | Conversion Rate / predicted CVR | CVR 是点击后转化率；pCVR 是预测的转化概率。 |
| eCPM | effective Cost Per Mille | 把不同计费方式换到统一的千次曝光价值尺度上排序。 |
| GSP | Generalized Second Price | 广义次价拍卖：排名看自己，付费看保住当前位置所需的次高价。 |
| oCPC | optimized CPC | 广告主给目标 CPA，系统根据 pCVR 动态计算点击出价。 |
| A/B | A/B Test，对照实验 | 将用户稳定分组，用数据判断新策略是否更好。 |
| AUC | Area Under the ROC Curve | 衡量模型把正样本排在负样本前面的能力，0.5 近似随机。 |
| NDCG@K | Normalized Discounted Cumulative Gain | 衡量 Top-K 排序质量，好结果越靠前得分越高。 |
| ONNX | Open Neural Network Exchange | Python 训练模型与 Java 在线推理之间的模型文件契约。 |
| gRPC | 基于 HTTP/2 + Protobuf 的 RPC | rec-engine 通过它调用 ad-serving、content-service 和 user-service。 |
| DDD | Domain-Driven Design | 按业务领域边界划分模块/服务，不是把每个 Maven 模块都拆成服务。 |

## 2. 搜索、Query 理解与向量检索

| 缩写 / 名词 | 全称 | 本项目中的意思 |
|---|---|---|
| IR | Information Retrieval，信息检索 | 从文档/物品集中找与 query 相关的结果。 |
| NLP | Natural Language Processing | 对 query 做归一化、分词、意图识别、改写和可选 LLM 增强。 |
| LLM | Large Language Model | 用于可选 query 纠错/意图/改写；失败时回落纯词法链路。 |
| FTS | Full-Text Search | PostgreSQL 对 `title_tsv` 做词法检索。 |
| GIN | Generalized Inverted Index | 为 PostgreSQL `tsvector` 加速的通用倒排索引。 |
| TF | Term Frequency | 某个词在当前文档中出现的频率。 |
| IDF | Inverse Document Frequency | 稀有词权重高、常见词权重低；由 `IdfJob` 离线计算并写 Redis。 |
| TF-IDF | Term Frequency-Inverse Document Frequency | 同时考虑文档内词频和全局稀有度的经典权重。 |
| BM25 | Best Matching 25 / Okapi BM25 | 常见词法排序算法。**本项目实际使用 PostgreSQL `ts_rank_cd`，不是完整 BM25 公式**。 |
| BGE | BAAI General Embedding | 本地 `bge-base-en-v1.5` ONNX 向量模型，输出 768 维内容向量。 |
| KNN | K-Nearest Neighbors | 查找距离最近的 K 个向量。 |
| ANN | Approximate Nearest Neighbor | 近似 KNN，用少量召回误差换低延迟。 |
| HNSW | Hierarchical Navigable Small World | 多层小世界图索引；`ef_search` 影响查询质量与速度。 |
| IVFFlat | Inverted File with Flat vectors | 先分簇再在命中簇内扫描原始向量的 ANN 索引；本项目主路使用 HNSW。 |
| RRF | Reciprocal Rank Fusion | 用 `1/(k+rank)` 按名次融合 LEXICAL 与 SEMANTIC。 |
| RQ-VAE | Residual-Quantized Variational Autoencoder | 把连续 item embedding 量化成多层离散语义 ID。 |
| TIGER | Transformer Index for Generative Recommenders | 自回归生成下一物品的语义 ID，再映射回 item。 |

## 3. 推荐召回、融合与探索

| 缩写 / 名词 | 全称 | 本项目中的意思 |
|---|---|---|
| ItemCF / I2I | Item-to-Item CF | 用户喜欢 A，就召回与 A 经常被同一批用户喜欢的物品。 |
| UserCF / U2U | User-to-User CF | 先找相似用户，再召回相似用户喜欢的物品。 |
| IUF | Inverse User Frequency | ItemCF 中降低超活跃用户对共现的贡献。 |
| IIF | Inverse Item Frequency | UserCF 中降低超热门物品对用户相似度的贡献。 |
| DSSM | Deep Structured Semantic Model | 双塔召回的常见范式：user 塔和 item 塔输出同空间向量。 |
| Two-Tower | 双塔模型 | item 向量离线烘焙，user 向量在线计算，再走 ANN 召回。 |
| MIND | Multi-Interest Network with Dynamic Routing | 把一个用户拆成多个兴趣向量分别检索。 |
| LightGCN | Light Graph Convolutional Network | 在 user-item 二部图上传播，获取高阶协同信号。 |
| BPR | Bayesian Personalized Ranking | 让正样本分数高于随机负样本的 pairwise 训练目标。 |
| MAB | Multi-Armed Bandit | 在“利用已知最优”与“探索未知候选”之间取舍。 |
| EE | Exploitation-Exploration | 利用-探索：给新物品/广告少量流量学习其价值。 |
| UCB | Upper Confidence Bound | “预估收益 + 不确定性奖励”，样本越少探索加成越高。 |
| LinUCB | Linear Upper Confidence Bound | 加入上下文特征的线性 UCB。 |
| TS | Thompson Sampling | 从收益后验分布采样决策，是 UCB 之外的探索策略。 |
| FTRL | Follow-The-Regularized-Leader | 适合稀疏特征的在线/近线增量学习算法。 |

## 7. 评估、校准与 A/B 实验

| 缩写 / 名词 | 全称 | 如何理解 |
|---|---|---|
| Precision@K | 前 K 个中有多少相关 | 关心“推出来的准不准”。 |
| Recall@K | 相关物品中有多少被前 K 个命中 | 它是评估指标，不是 Recall 召回阶段本身。 |
| HitRate@K | 命中率 | 对每个用户，前 K 个命中一个相关物品就记为命中。 |
| NDCG@K | Normalized Discounted Cumulative Gain | 同时看相关性和位置，好结果越靠前越好。 |
| MAP | Mean Average Precision | 先算每个用户的 Average Precision，再取平均。 |
| MRR | Mean Reciprocal Rank | 看第一个相关结果的排名倒数。 |
| ROC | Receiver Operating Characteristic | 不同阈值下 TPR/FPR 的曲线，AUC 是其下面积。 |
| ECE | Expected Calibration Error | 检查“预测 0.7 的样本是否真有约 70% 发生”。 |
| PSI | Population Stability Index | 比较特征/分数分布在不同时间的漂移。 |
| CI | Confidence Interval | 给指标一个不确定性范围，不只报点估计。 |
| CUPED | Controlled-experiment Using Pre-Experiment Data | 用实验前协变量降方差，让 A/B 实验更灵敏。 |
| ITT | Intention-To-Treat | 用户按首次实验分配组分析，避免事后选人产生偏差。 |

## 10. 最容易混淆的 10 组概念

1. **Recall 阶段 vs Recall@K 指标**：前者是候选生成阶段，后者是离线评估指标。
2. **CTR vs pCTR**：CTR 是真实统计，pCTR 是模型预测；同理 CVR vs pCVR。
3. **CVR vs CTCVR**：CVR 通常以点击为条件，CTCVR 是从曝光到转化的联合概率。
4. **Rank vs Rerank**：Rank 判断单个候选的分数，Rerank 优化整个列表。
5. **KNN vs ANN vs HNSW**：KNN 是目标问题，ANN 是近似加速方式，HNSW 是 ANN 索引。
6. **RRF vs 分数加权**：RRF 依赖名次，分数加权要求不同路分数已经可比。
7. **eCPM vs CPM**：CPM 是计费方式，eCPM 是统一竞价价值尺度。
8. **响应模型 vs Uplift**：前者问“谁会转化”，后者问“谁是因广告才转化”。
9. **ONNX 训练 vs ONNX 推理**：在 Python/PyTorch/LightGBM 中训练，导出 ONNX 后由 Java 推理。
10. **功能已实现 vs 生产效果已验证**：代码、契约和合成数据通过，不代表已用真实流量证明收益。
