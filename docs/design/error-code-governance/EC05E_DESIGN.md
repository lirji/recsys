# EC05e 种子与模拟作业的失败语义

基线bc7818679593b88bfcfb33132c2788243fd0d725，范围SeedAds、SimRecEvents、SimAdEvents及独占PG/分片/Redis测试。继续EC05既定范围，不真实执行清理或灌演示数据，不改SQL/schema/随机算法/写入批次/事务和数据归属。

三个作业先严格解析数字；生成数量、广告主数、创意数、用户数和展示长度要求为正，概率在[0,1]，广告模拟days/转化延迟非负且有限。参数或物品来源非法在clear之前拒绝。零数量原可伴随clear清空数据的行为有意纠正为参数错误；此任务不另造“只清理”命令。正常默认/随机种子/事件顺序保持。

SeedAds.clear沿用adDb先清、各分片表按枚举顺序尝试、再清倒排；adDb原及时失败继续及时失败，分片/Redis原继续策略保留但最终汇总抛JOB_SEED_CLEAR_FAILED并禁止继续生成。已完成的清理不撤销，错误文案明确部分旧数据可能已清除；不再输出“已清空”或“生成完成”。Redis未返回键集合也不能当清理成功。

SeedAds/SimRec的原clear后再查询目录时机保留，真实空目录抛JOB_GENERATION_INPUT_EMPTY并明确clear可能已生效，不能复用“完全未更新”的提示。SimAd无广告报告无输入；创意查询出错在写事件前失败，不能用空Map假装没有创意。确实成功读到空创意表仍允许NULL归因，带受控目录warning；已有部分广告无创意的原规则保持。

验证：复跑种子四源分片/向量/Snowflake/倒排与三模拟事务/真实晚失败/默认事件摘要；缺表创意失败无事件写入，真空创意有效NULL；实际FK拒绝某分片TRUNCATE证明部分清理和停止生成，真实Redis ACL拒绝KEYS证明不能伪成功，修复后可重跑。参数+clear保留旧数据，输入空+clear如实记录已清理效果。目录生成/前端错误专项、24compile、hygiene与显式Git交付。父EC05评估/报表/投影/共享CLI及EC06～08继续。
