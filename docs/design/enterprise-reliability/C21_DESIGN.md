# C21 非关键影子排序有界执行

2026-10-18，继续用户批准ER-S21，依赖S20已验证交付。范围仅ShadowRankRunner及其配置/验证，保留采样、主策略结果、top-K口径与已有RankRouter。曝光、资金、行为接受和Outbox不得进入可丢弃池。

## 决定

旧fixedThreadPool有无界队列且注释错误声称“队列满丢弃”；Future无人等待/取消，候选集合没有冻结。采用单独线程池默认1线程、队列8、AbortPolicy，总期限150ms（包含排队），最多512候选、top-K最多100。线程1～2、队列0～32、候选1～1024、期限1～1000ms为配置允许区间，重启生效；sampleRate必须有限且在[0,1]。默认enabled=false不变，不在本次启用。

每用户最多一个在途任务，全局最多threads+queue张票。过载/同用户重复/超大输入直接丢弃影子；主线程只做有界快照和非阻塞提交，不执行排序、等待排序或CallerRuns。业务参数显式不可变，复用S20的Micrometer/MDC传播和实际生命周期任务包装；不新增业务ThreadLocal。

一个独立守护维护线程每10ms扫描有界票集合，覆盖排队及执行时间，超时取消、立即移除排队，正在执行且忽略中断的计算继续占worker/user配额直到真正结束。维护线程只维护本地资源，不是持久化业务定时任务；仅有一个周期任务，不为每次请求创建无界延迟任务。关闭先拒绝新任务、停止扫描、取消所有任务并有界等待。deadline后结果不得计入成功/overlap；失败、超时、关闭、饱和、同用户拒绝、超大输入均可观测。

## 隔离边界与替代方案

拒绝共用召回池/CallerRuns或只加Future超时：会转移压力或掩盖仍运行的任务。保留同进程排序服务和模型；新增独立服务/模型副本超出原F19。独立worker/队列保证影子拥堵不占主请求或召回worker，S20给共享feature I/O设上限。物理CPU、Redis/DB和模型仍共享，不能宣称任意资源饱和下零影响；生产启用前必须按真实候选数、模型和副本数跑混合负载。默认小并发和有界输入只限定竞争上界；未满足主链路延迟预算时关闭shadow。

## 步骤与验收

1. Shadow配置与Runner：实际生命周期准入、冻结输入、统一期限与单维护线程、固定标签指标；不扩展其它异步事件池。
2. C21-01：队列满立即拒绝，200影子过载与正常主排序混合执行，实际worker峰值/队列/正常P95-P99有记录。
3. C21-02：不响应中断时worker仍占用、同user不能重新占队列；排队超时真正移除、迟到结果不发布、释放恢复。
4. C21-03：MDC/Observation传播恢复、调用方集合修改不改变影子输入；异常/关闭/禁用/采样边界和配置非法值。
5. C21-04：真实Redis+PG推荐HTTP与真实PG自然资格/回执/Outbox回归，关键事件接受/持久化不因shadow过载丢弃。验证代码路径无关键业务投递到影子池。
6. 同步运行手册/结果/CI与PLAN，Hygiene、正常提交合并push。回退可关闭shadow开关，代码回退不改变数据库或事件格式。
