# 平台安全与网关

> **解决什么**:多服务架构下,既要拦住外部未授权请求,又要保证服务间调用可信。本项目实现**两级零信任**(边缘 JWT + 内部 HMAC token)：通用 token/下游过滤在 `recsys-platform`，响应式边缘验证与身份重签在 `recsys-gateway`。

## 1. 两级零信任模型

```
Browser ──edge JWT(legacy HS256 或 Casdoor RS256/OIDC)──► Gateway
                               │ 剥离 Authorization + 伪造的 X-Internal-Auth
                               │ 重新签发内部 HMAC token
                               ▼
                    Downstream 服务(验内部 token → SecurityContext)
```
- **边缘 JWT**:面向浏览器/外部,网关处终结。应用缺省是 legacy HS256；Docker 栈默认设 `RECSYS_EDGE_CASDOOR=true` 与前端 OIDC 配套，使用 Casdoor JWKS/RS256。
- **内部 HMAC token**:东西向(服务间),网关重新签发,下游验签。外部**无法伪造**内部 token(不知 internal-secret),伪造的 `X-Internal-Auth` 头被网关剥离。

## 2. 内部 token(`InternalToken`)

- 纯 JDK HMAC-SHA256 自签:`base64url(subject\nroles\nscene\nexp).base64url(hmac)`。
- 篡改/过期 → 验签返回 null。
- 配置 `AuthProperties`(`recsys.security.*`):`enabled`、`internal-header`(`X-Internal-Auth`)、`internal-secret`、`edge-secret`(HS256,网关)、`token-ttl-seconds=300`、`permit-paths`。

## 3. 网关侧(`recsys-gateway`)

- `AuthController`:`/api/auth/login` 只用于 legacy 演示账号的 HS256 JWT(**网关原生,不路由下游**)。Casdoor 模式由前端经 OIDC 取 token，不调此登录端点。
- `GatewaySecurityConfig`:按 `recsys.security.casdoor.enabled` 在两种 decoder 间切换。legacy 验 HS256 `edge-secret` + `roles`；Casdoor 验 JWKS 签名、`iss`、租户 `owner`与 `aud`(精确 client 或 `<base>-org-<owner>` 家族)，再将 groups 映射为 ADMIN/ADVERTISER。
- `IdentityPropagationFilter`:重新签发内部 token,**剥离入站 `Authorization` + 伪造 `X-Internal-Auth`**,注入新鲜 token。

## 4. 下游 Servlet 侧(`recsys-platform`)

- `InternalSecurityConfig`:链**永远注册**。`enabled=true` → stateless + permit-paths + `authenticated()` + `InternalTokenAuthFilter`;`enabled=false` → 显式 `permitAll()`(**不会自锁死**)。
- `InternalTokenAuthFilter`:验 token → 填 SecurityContext。
- `MethodSecurityConfig`:`@PreAuthorize` 与同一开关联动(一键关)。
- `GlobalExceptionHandler` + `ApiError`:统一错误契约。
- `RECSYS_SECURITY_ENABLED` 横跨所有服务——**网关本地也要设 false**,否则 `/api/advertiser` 等 401(dev-local.sh 已处理这个坑)。

## 5. 网关路由与治理

- 反应式 Spring Cloud Gateway :8080，默认路由目标是 Nacos `lb://recsys-*`；无 Nacos 时用 `static` profile 切到 `application-static.yml` 的可参数化 `http://localhost:*` 目标。
- 路由:rec-engine 收 `/api/{recommend,search,search-ads,feed,query,user,ad,experiment}/**`;behavior/advertiser/console 各自前缀。**ad-serving 刻意不路由**(计费经 rec-engine→gRPC)。
- **Nacos discovery 默认开**(`NACOS_DISCOVERY=true`)；`dev-local.sh` 容器栈也默认用 `lb://`。纯本地无 Nacos 才切 `static` profile。
- **ratelimit profile**(opt-in,需 Redis):`RequestRateLimiter` Redis 令牌桶,`userKeyResolver` = userId→IP→global 分桶,`GATEWAY_RATE_LIMIT_RPS:50`/`_BURST:100`,超限 429。默认关、无 Redis 也能起。

## 6. gRPC 侧安全(已闭环,2026-07 服务端硬化)

- 客户端拦截器 `InternalAuthGrpcClientInterceptor` 已在 rec-engine/advertiser 接线(`GrpcClientHardeningConfig`),会签 HMAC token 进 metadata。
- 服务端拦截器已注册:三个 gRPC 服务(ad-serving/content-service/user-service)均通过 `GrpcServerHardeningConfig` 的 `GlobalServerInterceptorConfigurer` 注册 `InternalAuthGrpcServerInterceptor`,校验客户端 HMAC 内部令牌——`server-auth-required` **默认 true**(缺/错令牌返 UNAUTHENTICATED),可置 false 灰度软启;幂等读另挂 Resilience4j 瞬时重试(`GrpcRetryablePredicate`)。东西向 HTTP 与 gRPC 双路径零信任闭环。

## 7. 广告主细粒度归属判权

网关的 ADMIN/ADVERTISER 只是粗粒度 RBAC，不能回答“这个广告主是不是你的”。`recsys-advertiser` 通过 `AdvertiserAuthz` 接 auth-platform/SpiceDB，按 `advertiser:{id}` 判 `view/edit/manage`，平台级判 `administrate/review`。

- `RECSYS_AUTHZ_MODE=disabled|shadow|enforce`，默认 disabled；拼错 mode 启动即失败。
- enforce 下 deny 返 403，判权依赖故障返 503 fail-closed；shadow 只记 `would-deny` 并放行。
- 创建广告主时归属双写与业务事务绑定；enforce 失败回滚，避免无 owner 孤儿。详见 `docs/09-权限接入auth-platform.md`。

## 8. 踩坑

1. **网关不设 `RECSYS_SECURITY_ENABLED=false` 本地会 401**——网关自身也在鉴权链上。
2. **enabled=false 用显式 permitAll**——而非不注册链,避免误配自锁死。
3. **内部 token TTL 300s**——服务间调用别缓存过期 token。
4. **gRPC 服务端验签靠全局注册**——net.devh 的服务端拦截器必须经 `GlobalServerInterceptorConfigurer` 挂载;只写拦截器类不注册 = 客户端签、服务端不验的假安全。
5. **Casdoor 切换必须前后端成对**——后端 `RECSYS_EDGE_CASDOOR=true`时前端应用 OIDC；回滚 legacy 时同时切 `CONSOLE_AUTH_MODE=legacy` 与 `RECSYS_EDGE_CASDOOR=false`。

## 9. 面试要点

- **两级零信任**:边缘 JWT(外部)+ 内部 HMAC(东西向),网关重签发、剥离伪造头,外部无法伪造内部身份。
- **为什么内部 token 而非透传 JWT**:最小权限 + 短 TTL + 服务间信任边界清晰;网关是唯一签发点。
- **一个开关全局启停**:`RECSYS_SECURITY_ENABLED`,关时显式 permitAll 不自锁。
- **网关限流**:Redis 令牌桶,userId→IP→global 分级 key,opt-in profile。
- **边缘两模式**:legacy HS256 便于本地演示；Casdoor 用 JWKS/RS256 + issuer/audience/owner 守租户边界。
- **纵深防御的第三层**:网关粗粒度 RBAC 之外,advertiser 管理面另接 auth-platform/SpiceDB 细粒度归属判权;gRPC 服务端默认强制验内部令牌(`server-auth-required=true`)。
