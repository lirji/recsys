# A/B 实验与分层

> **解决什么**:任何推荐/广告改动都要用数据证明有效。本项目实现**分层实验**(多层正交、可组合)+ 确定性分桶 + 显著性检验 + CUPED 降方差。

## 1. 分层实验(layered experiment)

四层各是独立实验,各有自己的 salt 和 variants,**互相正交、可任意组合**:

| 层 | 切什么 | 默认变体 |
|---|---|---|
| `recall` | 启用的召回路集合(`channels`) | base / plus(plus 含 TWO_TOWER/GENERATIVE/TIGER) |
| `rank` | 排序策略(v1/onnx…)+ 融合权重 | v1 / onnx |
| `rerank` | 重排策略 + 参数 | diversity / mmr |
| `ad` | 广告变体(reserve-price 等覆盖) | base / high-reserve |

recall×rank×rerank = 8 种组合。配置 `recsys.experiment.layers.*`,默认 `enabled=true` 各 50/50。

## 2. 确定性分桶

```
bucket = floorMod( (userId + "|" + salt).hashCode(), 100 )
→ 按 variant 权重累积命中
```
- **确定性**:同 userId + 同 salt 永远同桶。故结果缓存按 userId 即可,无需按 bucket 拆。
- `enabled=false` 时每层取第一个 variant 作基线。
- **`ad` 层单独分桶**:`ExperimentService.adVariant` 独立分桶,**不混入推荐 bucketTag**,`ad_event.ad_bucket` 落库供广告分层 A/B。

## 3. 动态覆盖(不重启改实验)

- Redis `recsys:exp`(`ExperimentOverrideService`),30s 缓存 + `invalidate()`。
- 管理面 `/api/experiment`:GET 快照 / POST 开关·放量·停止 / DELETE 清空。改实验不重启。

## 4. 埋点与归因

- `ExposureLogger` 每次实际交付（包括推荐缓存命中）为每个 item 生成独立 UUID `exposureId`，异步写 `user_behavior(action=IMPRESSION,bucket,position,exposure_id)`；缓存只保存候选与 bucket，绝不复用旧交付身份。
- Redis 精确键 `expo:id:{exposureId}` 保存 user/item/bucket，`expo:latest:{user}:{item}` 兼容旧客户端缺 ID，旧 `expo:{user}:{item}=bucket` 在滚动升级期继续双写。行为服务校验 user/item，客户端 bucket 不作为实验真值。
- 点击来自 `POST /api/behavior`，点击类行为使用服务端接收时间；`user_behavior` 的部分唯一索引保证同 `exposure_id` 的 CLICK 最多一条，重复请求仍 200，但不重复计指标或发 Kafka。报表只把 `CLICK` 计入 CTR。
- 存量库发布必须 schema-first 执行 `psql -f recsys-offline/sql/16_exposure_click_idempotency.sql`；initdb 的 `01_schema.sql` 只覆盖新卷。Redis 归因在响应前同步写，曝光 DB 行仍异步。

## 5. 统计显著性(`ab-report` + 纯函数 `AbStats`)

`ab-report` 作业基于曝光/点击日志逐桶算 CTR,并对基线桶做:
- **Wilson 95% 置信区间**(小样本比例区间比正态近似稳)。
- **两比例 z 检验** → p 值 / 是否显著(`--alpha` 默认 0.05)/ lift。
- **每臂最小样本量**(检测该 lift 所需,`--power`)。
- **AA 校验**:把同策略两桶当 A/B 跑,若显著 → 分桶/埋点有偏(健康度自检)。

写 `eval/ab-report-<ts>.csv`;`--baseline`/`--alpha`/`--power` 可调。

传 `--cuped-pre-days=N` 启用 user 级 CUPED，且必须提供 `--since` 作为实验开始点：

```bash
mvn -pl recsys-offline spring-boot:run \
  -Dspring-boot.run.arguments="--job=ab-report --since=2026-08-01 --until=2026-09-01 --cuped-pre-days=30 --scene=home"
```

- pre 窗口严格为 `[since-N days,since)`，post 为 `[since,until)`，两段使用同一 scene 口径。
- user 为随机化/聚类单位；ratio metric 先线性化成 `clicks_i − pooledCTR×impressions_i`，控制变量是实验前同口径影响函数。调整项不乘 post 曝光，避免 treatment 改变活跃度时引入 post-treatment bias；raw mean 仍严格等于总点击/总曝光。
- θ 在全部实验臂 pooled 拟合并预先固定使用（不按 post outcome 选择是否启用）；SE 用 user-cluster sandwich 口径，SE=0 或前置样本不足时不输出伪显著性，`variance_reduction` 仅作诊断。
- `--cuped-min-users` 默认要求每臂至少 30 个有前置数据的 user。跨完整 bucket 的 user 按首次曝光做 ITT；开启 CUPED 后 raw/adjusted 列使用同一 ITT 人群，并输出 `cuped_crossover_users` 污染数。
- 启用 CUPED 时 CSV 为 24 列；关闭时保持旧 12 列契约。
- user 是随机化单位时，正式判断优先看 user-cluster 的 `cuped_p_value`；旧 `p_value` 沿用 impression 独立近似，仅作兼容参考。多个 treatment 同时对基线检验时还需在分析侧做 Holm/FDR 修正。

## 6. 踩坑

1. **按 bucket 拆缓存是多余的**——确定性分桶下同 userId 恒定同桶,缓存 key 用 userId 即可。
2. **IMPRESSION 埋点必须带 bucket + position**,否则无法做分桶 CTR / PAL 闭环。
3. **ad 层不能混入推荐 bucketTag**——否则推荐分桶 CTR 被广告变体污染。
4. **不做 AA 校验直接信 A/B 结果**——分桶哈希偏斜/埋点丢失会造成假显著。
5. **用实验期数据做 CUPED 协变量**——会产生 treatment leakage；协变量只能来自严格前置窗口。
6. **事后删除跨桶用户**——可能形成 post-treatment selection；本实现用首次曝光 ITT，并把污染率作为实验健康度信号。
7. ~~**重复 CLICK 没有幂等键**~~——已修：曝光 UUID 贯通响应/Redis/DB，PostgreSQL 部分唯一索引是并发幂等权威；月分区场景需改用独立全局 `click_dedupe` 表，因为分区唯一约束必须包含 `ts`。

## 7. 面试要点

- **分层实验为什么正交**:各层独立 salt,组合空间大、复用流量。
- **确定性分桶**:hash(userId|salt),同用户恒定,可缓存。
- **Wilson 区间 vs 正态近似**:小样本/极端比例时 Wilson 更稳。
- **AA 测试**:同策略对照,验证分桶/埋点无偏,是上线 A/B 前的必要体检。
- **最小样本量/功效**:能检测多大 lift 取决于样本量,报告要给出。
- **CUPED**:用实验前、与目标指标相关的协变量降低方差；不能修复分桶偏差、埋点错误或样本不足。
