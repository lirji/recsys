# 工程化 · 容器编排与可观测

> **解决什么**:让这套多服务系统"一键本地跑通、可容器化、可上 k8s、可观测、可 CI 守门"。这些是脚手架"面向生产"承诺的兑现。

## 1. 本地一键起(`scripts/dev-local.sh`,全链路容器化)

**编排已拆成两个职责边界**:`docker/docker-compose.yml` 负责 8 个 Java 应用和前端；相邻 `../dev-infra/compose.yaml` 负责 recsys 专用 PostgreSQL/Redis/Kafka/Nacos/SpiceDB/观测组件。`scripts/dev-local.sh` 是联动入口:
- `up`:先以 dev-infra `recsys` profile 启动 PG/Redis/Kafka/Nacos，再以应用 Compose 的 `apps + console` profiles 起 8 app + 前端，最后等待网关健康。跨 Compose 无 `depends_on`，因此顺序由脚本保证。
- `rebuild <svc>`:改了后端代码 → 重建该服务镜像并重启(容器化下改代码需重建)。
- `frontend`:前端热开发,宿主机跑 Vite → 容器网关 `$GATEWAY_PORT`。
- `build`/`status`/`down`/`restart`/`logs <svc>`/`infra`/`infra-stop`/`obs`/`authz` 子命令。`down` 只删应用容器，dev-infra 与数据卷保留；`infra-stop` 才停 recsys 基础设施。
- **固化在编排里的关键配置**:①dev 默认 `RECSYS_SECURITY_ENABLED=false`;②rec-engine/advertiser/ad-serving 注入指向 `recsys-postgres` 的 `PG_JDBC_URL`+`PG_DS1_JDBC_URL`;③dev-infra 新卷挂载 `recsys-offline/sql/` 并通过 `04b_ds1_bootstrap.sql` 建 `recsys_ds1`;④apps 默认 Nacos 发现，rec-engine 通过 gRPC 调 ad/content/user。
- 端口冲突时写 `scripts/dev-local.env`(**只改容器对宿主暴露的端口**)。默认 recsys 基础设施使用 dev-infra 高位端口；若同级 auth-platform 存在，脚本还会读取其中央端口注册表统一 UI 入口。

## 2. Compose profiles 与所有权

| Compose | profile | 起什么 |
|---|---|---|
| `docker/docker-compose.yml` | `apps` | 8 个 Java 服务；网关为宿主统一 API 入口，内部用 Nacos + gRPC |
| `docker/docker-compose.yml` | `console` | nginx 托管 React SPA，反代 `/api`到 `gateway:8080` |
| `../dev-infra/compose.yaml` | `recsys` | pgvector PostgreSQL、Redis、Kafka、Nacos |
| `../dev-infra/compose.yaml` | `recsys-obs` | Prometheus、Grafana、Tempo、Alertmanager、webhook logger |
| `../dev-infra/compose.yaml` | `recsys-authz` | recsys 专用 SpiceDB 及迁移任务 |
| 应用 Compose | `legacy-*` | 回滚时使用的旧基础设施/观测/判权 profiles，非日常入口 |

手工跑应用 Compose 前必须已有外部 `dev-infra` network 和基础设施；日常优先用 `scripts/dev-local.sh`，避免漏掉跨 Compose 启动顺序。

## 3. 容器化 & k8s

- **一个参数化 Dockerfile(`docker/Dockerfile`)** 服务所有 Spring Boot app:`--build-arg MODULE/PORT`,先 COPY 根 POM + 22 个模块 POM 做依赖层缓存，再 `-pl MODULE -am` 打包；运行时为 `eclipse-temurin:21-jre` 非 root(1001)。构建上下文=仓库根(`context: ..`),`.dockerignore` 仍在仓库根。recsys-streaming 除外(需 `--add-opens`)。
- **k8s**(`deploy/k8s/`,kustomize base + dev/prod overlay):三探针,**readiness = `/actuator/health/readiness`**(含 `ModelReadinessHealthIndicator`——模型策略但 ONNX 没加载 → readiness DOWN,k8s 不导流)。rec-engine startupProbe(failureThreshold 30);env `AD_SERVING_MODE=in-process`(kill-switch,直到 money-chain-gate 绿)、`CONTENT/USER_SERVING_MODE=grpc`。

## 4. 可观测(`docker/monitoring/` + dev-infra)

观测配置仍由本仓库 `docker/monitoring/` 版本化，日常容器实例由 dev-infra `recsys-obs` profile 管理，`scripts/dev-local.sh obs` 负责启动并等待 Tempo。

- **Prometheus**:8 个 host target;指标 `recsys_recommend_duration_seconds_*`(P50/P95/P99)、`recsys_ad_duration_seconds_*`、缓存命中率、模型回退率、分桶曝光/点击。
- **告警规则**(`alert-rules.yml`):推荐 SLO 99.5%/P99<200ms 多窗口 burn-rate(14.4×/3×);RecEngineDown、RecommendErrorBudgetBurn Fast/Slow、RankModelFallbackHigh、CacheHitRatioLow、EmptyRecallSpike;广告 SLI(P99<300ms、fill、CTR、eCPM、invalid-click)+ AdServingLatencyP99High、AdFillRatioLow、AdInvalidClickSpike。
- **Alertmanager** → `webhook-logger:5001`(Slack/钉钉/飞书 demo)。
- **Grafana**(:3001):datasource + 2 看板(`recsys-online.json`、`recsys-ads.json`)。
- **Tempo**:OTLP 分布式追踪后端(P2)。
- **console-api BFF 观测**:`SystemHealthService`(并行探 8 app + 2 passive job)、`SystemMetricsService`(PromQL,never throws)、`SystemOverviewService`(静态模块图),供前端总览/诊断/告警页。

## 5. 熔断(Resilience4j)

重外呼加熔断快速失败到降级:
- `GeminiEmbeddingClient`(gemini-embedding)。
- `VectorRecaller` 的 pgvector ANN(pgvector-recall,pg 宕 → VECTOR 路快速返回空、其它路兜底)。
- gRPC 客户端每 RPC 熔断(见 [16](16-微服务拆分与gRPC.md))。
- 配置在 rec-engine `application.yml` 的 `resilience4j.circuitbreaker`。

| 机制 | 粒度 | 存储 |

## 8. 踩坑

1. **应用与基础设施不在同一 Compose**——应用文件在 `docker/`，基础设施在 `../dev-infra`；手工只起 `apps` 会因缺 network/PG/Redis/Nacos 失败。
2. **网关不关 security 本地 401**——`RECSYS_SECURITY_ENABLED=false`(compose 已注入)。
3. **分库 ds_1 未建则分片服务启动即挂**——存量库手工跑 `recsys-offline/sql/04_ad_sharding.sql`；dev-infra 新卷由 `04b_ds1_bootstrap.sql`(随整个 SQL 目录挂进 initdb)首启自动建。
4. **全容器化下改代码不重建镜像不生效**——`dev-local.sh rebuild <svc>`;要即改即跑用宿主机 mvn 模式(见 08)。
5. **端口覆盖只改宿主暴露端口**——容器间用服务名+标准内部端口,改 `*_PORT` 不影响互通。
6. **重训模型后不 clean install**——ONNX 陈旧,`target/classes` 留旧资源。
7. **readiness 探针含模型就绪**——ONNX 没加载会 DOWN,别用 liveness 代替。
8. **`down` 不会停 dev-infra**——这是为了保留中间件与数据；需要停基础设施时用 `infra-stop`，不要误以为脚本泄漏了容器。

## 9. 面试要点

- **readiness vs liveness**:readiness 含 `ModelReadinessHealthIndicator`,模型没就绪不导流;liveness 只看进程活着。
- **money-chain-gate**:计费相关测试单独 gate,必过才允许拆 ad-serving(kill-switch `AD_SERVING_MODE=in-process`)。
- **多窗口 burn-rate 告警**:快窗(14.4×)+ 慢窗(3×)组合,兼顾灵敏与抗抖。
- **三层配置热更**:Nacos(结构化)/ Redis tuning(轻量旋钮)/ Redis exp(实验),都不重启。
- **一个 Dockerfile 参数化所有服务**:MODULE/PORT build-arg,根 POM + 全模块 POM 分层缓存加速。
